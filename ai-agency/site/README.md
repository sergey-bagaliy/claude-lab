# Сайт агентства (лендинг для GitHub Pages)

Одностраничный сайт ИИ-агентства. В нём:
- услуги;
- демо-примеры работы бота;
- пакеты с ценами;
- форма заявки;
- политика и согласие на обработку персональных данных.

Сайт статический, без сборки и библиотек: только HTML, CSS и немного JavaScript.

## Что внутри

```
site/
├── index.html      главная страница
├── privacy.html    политика обработки персональных данных (шаблон)
├── consent.html    согласие на обработку данных, отдельным документом (шаблон)
├── config.js       ВСЕ настройки: название, контакты, реквизиты, адрес приёма заявок
├── assets/
│   ├── style.css   оформление (светлая и тёмная тема)
│   └── app.js      демо-чаты и отправка формы
└── .nojekyll       служебный файл для GitHub Pages
```

## Шаг 1. Впишите свои данные

Откройте `config.js` в любом редакторе и заполните:

| Поле | Что вписать |
|---|---|
| `brand` | название агентства (сейчас рабочее «Умный администратор») |
| `phone`, `email`, `telegram` | контакты. Пустые поля на сайте не показываются |
| `operatorName`, `operatorInn`, `operatorAddress` | реквизиты для политики и согласия (ИП или ООО) |
| `formEndpoint` | адрес, куда форма отправляет заявки (шаг 2) |

> ⚠️ Сайт публичный: всё, что в `config.js`, видят все посетители.
> **Не вписывайте туда токены ботов, API-ключи и пароли.**

Проверить сайт до публикации можно двумя способами.
Первый — просто открыть `index.html` в браузере. Второй — запустить локальный сервер:

```bash
cd ai-agency/site
```

```bash
python -m http.server 8000
```

После этого откройте в браузере `http://localhost:8000`.

## Шаг 2. Форма заявки

Форма отправляет заявку POST-запросом в формате JSON на адрес из `formEndpoint`.
В заявку попадают:
- имя;
- телефон;
- тип бизнеса;
- пакет;
- комментарий;
- время согласия.

Варианты:

1. **Свой обработчик на сервере в России** — самый надёжный вариант с точки зрения 152-ФЗ: данные граждан РФ
   должны записываться в базы данных на территории РФ. Например, небольшой скрипт на том же сервере,
   где работает бот: принимает заявку и пересылает её вам в Telegram. Токен бота хранится на сервере, а не на сайте.
2. **Сервис приёма форм** (например, Formspree). Подключается за пять минут.
   Но проверьте, где сервис хранит данные и подходит ли это под требования о локализации.
3. **Ничего не настраивать.** Если `formEndpoint` пуст, а `email` заполнен, форма откроет почтовую программу посетителя с готовым письмом.

Без согласия (галочки) форма заявку не отправит. Есть скрытое поле-ловушка от спам-ботов.

## Шаг 3. Публикация на GitHub Pages

В репозитории уже есть автоматическая публикация: `.github/workflows/pages.yml`.

1. На GitHub откройте репозиторий → **Settings** → **Pages**.
2. В **Build and deployment → Source** выберите **GitHub Actions**.
3. Слейте изменения в ветку `main`. Публикация запустится сама при любом изменении в `ai-agency/site/`.
   Запустить её вручную можно на вкладке **Actions** → «Deploy agency site to GitHub Pages» → **Run workflow**.
4. Адрес сайта появится в **Settings → Pages**, обычно это `https://<логин>.github.io/<репозиторий>/`.

Свой домен: добавьте его в **Settings → Pages → Custom domain** и настройте DNS у регистратора
по [инструкции GitHub](https://docs.github.com/ru/pages/configuring-a-custom-domain-for-your-github-pages-site).

## Что важно не забыть

- **Пакеты и цены** в `index.html` — это ориентир из исследования (`ai-agency/research`).
  Пересмотрите их перед публикацией.
- **Политика и согласие** — шаблоны. Заполните пропуски, выделенные цветом, и согласуйте с юристом.
- **Отзывы и кейсы.** На сайте их сейчас нет специально: выдуманные отзывы вводят клиентов в заблуждение.
  Добавляйте только реальные кейсы, с цифрами и с разрешения клиента.
- **Цифры в блоке «Почему это важно»** взяты из исследования, у каждой есть ссылка на источник.
  Если меняете цифру, меняйте и ссылку.
