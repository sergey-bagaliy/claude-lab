# ИИ-администратор для записи клиентов (Telegram-бот)

Шаблонный бот для малого бизнеса: стоматологии, автосервиса, салона и т. п.
Бот на **Python** (aiogram 3) с ИИ **Claude** (официальный SDK `anthropic`).
Под нишу настраивается **одним YAML-файлом**, без правки кода.

## Что умеет

| Функция | Как работает |
|---|---|
| Отвечает на вопросы | Claude отвечает только по базе знаний из конфига: услуги, график, частые вопросы, свободный текст. Чего нет в базе, не придумывает: предлагает позвать администратора. |
| Записывает на свободное время | Двумя путями: кнопками («📅 Записаться» → услуга → день → время → имя → телефон → подтверждение) или в диалоге («запишите меня на чистку в пятницу после обеда»). |
| Не допускает двойной записи | Учитывает часы работы, перерывы, праздники, длительность услуги, минимальное время до записи и число мест (кресел, подъёмников). Проверка атомарная, поэтому два клиента одно время не займут. |
| Пересылает заявки владельцу | Новая запись, отмена и просьба «позвать человека» сразу приходят владельцу в Telegram. |
| Записи клиента | «🗓 Мои записи»: клиент видит свои записи и может их отменить. |
| Соблюдает 152-ФЗ (база) | Без согласия на обработку данных не ведёт диалог и не записывает. Хранит дату согласия. По команде `/delete_my_data` удаляет данные клиента. |
| Команды владельца | `/schedule` — записи на 7 дней, `/myid` — узнать ID чата. |

**Пример из жизни.** Клиент в 23:40 пишет стоматологии: «Болит зуб, можно завтра?».
Бот предлагает свободное время на завтра, спрашивает имя и телефон, ждёт подтверждения и записывает.
Владелец утром видит в Telegram: «🆕 Новая запись: Консультация, 05.11 в 10:00, Иван, +7918…».

## Шаг 1. Установите Python

Нужен Python 3.10 или новее: [python.org/downloads](https://www.python.org/downloads/).
На Windows при установке отметьте галочку **Add Python to PATH**.

Проверка в терминале (Windows: PowerShell):

```bash
python --version
```

## Шаг 2. Скачайте проект и установите библиотеки

```bash
cd ai-agency/bot
```

```bash
python -m venv .venv
```

Активируйте окружение. На Linux или macOS:

```bash
source .venv/bin/activate
```

На Windows (PowerShell):

```bash
.venv\Scripts\Activate.ps1
```

Установите библиотеки:

```bash
pip install -r requirements.txt
```

## Шаг 3. Ключи

Ключи **хранятся только в переменных окружения**. В код, конфиги и git их не кладём.

1. **Токен бота.** Откройте [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя → скопируйте токен.
2. **Ключ Anthropic.** Получите в [console.anthropic.com](https://console.anthropic.com/) → API Keys.
   Сначала прочитайте раздел «Важно: ограничения» ниже.
3. Скопируйте шаблон и впишите значения:

```bash
cp .env.example .env
```

Файл `.env` уже в `.gitignore`, поэтому в репозиторий он не попадёт.
Подгрузите переменные из него. На Linux или macOS:

```bash
set -a; source .env; set +a
```

На Windows (PowerShell):

```bash
Get-Content .env | Where-Object { $_ -match '^\s*[^#].*=' } | ForEach-Object { $k, $v = $_ -split '=', 2; [Environment]::SetEnvironmentVariable($k.Trim(), $v.Trim(), 'Process') }
```

| Переменная | Обязательна | Что это |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен от @BotFather |
| `ANTHROPIC_API_KEY` | да | ключ API Anthropic |
| `OWNER_CHAT_ID` | желательно | куда слать заявки (см. шаг 5) |
| `BUSINESS_CONFIG` | нет | путь к конфигу ниши, по умолчанию `configs/dentistry.yaml` |
| `DB_PATH` | нет | файл базы, по умолчанию `data/bot.db` |
| `ANTHROPIC_MODEL` | нет | модель Claude, по умолчанию `claude-opus-5-5` |
| `ANTHROPIC_EFFORT` | нет | глубина размышлений: `low` (по умолчанию) … `max` |
| `HISTORY_MESSAGES` | нет | сколько последних сообщений диалога помнит бот (20) |

## Шаг 4. Настройте под свой бизнес

Скопируйте пример ближайшей ниши и отредактируйте его в любом текстовом редакторе:

```bash
cp configs/dentistry.yaml configs/my_business.yaml
```

Затем впишите `BUSINESS_CONFIG=configs/my_business.yaml` в `.env`.

| Раздел | Что заполнить |
|---|---|
| `business` | название, адрес, телефон, **ссылка на политику ПДн**, кто оператор данных (ООО или ИП, ИНН) |
| `assistant` | имя бота, тон, приветствие, особые правила ниши (например, «не ставь диагнозы») |
| `booking.comment_prompt` | доп. вопрос перед записью: для автосервиса «марка, модель, год». Для клиник оставьте пустым: жалобы — это данные о здоровье |
| `schedule` | часы работы по дням, перерывы, праздники, шаг сетки, на сколько дней вперёд открыта запись, **capacity** — сколько клиентов одновременно |
| `services` | `id` латиницей, название, длительность в минутах, цена строкой. Если цену не указать, бот скажет «стоимость уточняет администратор» |
| `faq`, `knowledge` | частые вопросы и любые сведения: парковка, оплата, гарантия… **Бот знает только то, что здесь написано** |

В примерах `configs/dentistry.yaml` и `configs/autoservice.yaml` компании вымышленные, а цены пустые.
Это заглушки: перед запуском замените их реальными данными.
Если в конфиге ошибка, бот при запуске скажет, в какой строке и что исправить.

## Шаг 5. Запуск

```bash
python -m admin_bot
```

1. Напишите своему боту в Telegram `/myid` — он пришлёт число.
2. Впишите его в `.env` как `OWNER_CHAT_ID=...` и перезапустите бота (Ctrl+C, затем снова команда выше).
   Теперь заявки будут приходить вам.
3. Проверьте путь клиента: `/start` → согласие → вопрос → «📅 Записаться».

Чтобы заявки получала группа администраторов, добавьте бота в группу, напишите там `/myid`
и укажите в `OWNER_CHAT_ID` полученное число. Для группы оно отрицательное.

## Тесты

Тесты не ходят в интернет: API Anthropic и Telegram в них подменены.

```bash
pip install -r requirements-dev.txt
```

```bash
python -m pytest
```

Что проверяется:
- расчёт свободного времени: перерывы, выходные, вместимость;
- защита от двойной записи и запись без согласия;
- цикл инструментов Claude: свободные слоты → запись → ответ;
- обработка отказов и ошибок API;
- сценарий записи кнопками для стоматологии и автосервиса;
- сквозной тест через настоящий диспетчер aiogram;
- что в репозитории нет ключей и токенов.

## Запуск на сервере (Docker)

Бот работает постоянно, поэтому ему нужен сервер (VPS) с Docker.

```bash
docker build -t admin-bot .
```

```bash
docker run -d --name admin-bot --restart unless-stopped --env-file .env -v "$(pwd)/data:/app/data" admin-bot
```

Ключи передаются через `--env-file` и внутрь образа не попадают.
База `data/bot.db` лежит на сервере: делайте её резервные копии.

## Как устроено

```
bot/
├── configs/                 конфиги ниш (YAML): dentistry.yaml, autoservice.yaml
├── admin_bot/
│   ├── __main__.py          запуск: python -m admin_bot
│   ├── settings.py          переменные окружения (ключи только отсюда)
│   ├── business.py          загрузка и проверка YAML-конфига
│   ├── scheduling.py        расчёт свободного времени
│   ├── storage.py           SQLite: записи, согласия, история
│   ├── booking.py           правила записи и уведомления владельцу
│   ├── ai.py                Claude: системный промпт, инструменты, цикл вызовов
│   ├── handlers.py          обработчики Telegram (меню, кнопки, диалог)
│   ├── keyboards.py         кнопки
│   └── notify.py            отправка уведомлений владельцу
└── tests/                   тесты (pytest) с подменой API
```

Как ИИ записывает клиента. У Claude есть четыре инструмента:
- `get_free_slots` — свободное время;
- `book_appointment` — записать;
- `my_bookings` — записи клиента;
- `handoff_to_admin` — позвать человека.

Модель только просит выполнить действие. Выполняет его наш код со всеми проверками: свободно ли время, есть ли согласие, корректен ли телефон.
Поэтому даже при ошибке модели запись на занятое время невозможна.

Технические детали для разработчика:
- системный промпт стабилен и кэшируется (prompt caching), а текущая дата идёт в сообщении клиента;
- инструменты объявлены со `strict: true`;
- для моделей, которые это поддерживают, включён серверный запасной вариант на случай отказа модели (`fallbacks: "default"`, beta-заголовок `server-side-fallback-2026-07-01`). Если вам это не нужно, удалите ветку с `FALLBACK_MODELS` в `ai.py`.

## Модель и стоимость

По умолчанию используется `claude-opus-5-5`. Модель меняется переменной `ANTHROPIC_MODEL`.
Цены API Anthropic за 1 млн токенов (вход / выход), по [официальной странице цен](https://platform.claude.com/docs/en/about-claude/pricing):

| Модель | Вход | Выход |
|---|---|---|
| `claude-opus-5-5` | $4 | $20 |
| `claude-sonnet-5-5` | $2 | $10 |
| `claude-haiku-5-5` | $0,10 | $0,50 |

Стоимость одного диалога зависит от длины базы знаний и переписки. Её нужно измерить на ваших данных:
в ответе API есть поле `usage`, а в консоли Anthropic — расход по дням.
Выбор модели — это компромисс цены и качества, его делаете вы.

## Важно: ограничения и право

Это не юридическая консультация. Перед запуском у реального клиента проверьте всё с юристом.

1. **Доступность API Anthropic.** На странице [anthropic.com/supported-countries](https://www.anthropic.com/supported-countries) (проверено 04.11.2026) Россия в списке поддерживаемых стран **не значится**.
   Использовать API можно только в соответствии с условиями Anthropic. Проверьте, подходит ли это вашей ситуации.
   Вся работа с ИИ собрана в одном файле `admin_bot/ai.py`. При необходимости его можно переписать под другую модель, в том числе российскую, не трогая запись, базу и Telegram-часть.
2. **152-ФЗ.**
   - У клиента-бизнеса должна быть опубликованная политика обработки ПДн (ссылка в конфиге) и уведомление в Роскомнадзор.
   - Согласие клиента бот запрашивает отдельно и хранит его дату.
   - Переписка уходит в сервис ИИ за рубежом, а это трансграничная передача: о ней нужно уведомлять РКН, и она отражена в тексте согласия по умолчанию. Текст согласия можно заменить своим (`business.consent_text`).
   - База с записями должна лежать на сервере в России (локализация).
   - Для клиник: не собирайте в боте симптомы и жалобы. Это данные о здоровье, особая категория.
3. **Telegram в России.** По сообщениям [РБК от 10.02.2026](https://www.rbc.ru/technology_and_media/10/02/2026/698b21a39a79473017a3cb4a), Роскомнадзор начал ограничивать работу Telegram.
   Поэтому бот лучше подключать как **один из каналов** записи, рядом с телефоном и сайтом.

## Что можно добавить

- Напоминание клиенту за день до визита (снижает неявки).
- Запись напрямую в YCLIENTS, IDENT или 1С через их API вместо встроенной базы.
- Второй канал: MAX или виджет на сайте. Логика записи и ИИ при этом остаются прежними.

## Частые проблемы

| Сообщение | Что сделать |
|---|---|
| `Не заданы переменные окружения: …` | не подгружен `.env` (шаг 3) |
| `Файл конфига не найден` | проверьте `BUSINESS_CONFIG` и что запускаете из папки `bot` |
| `schedule.working_hours.mon: ожидается интервал…` | время пишется так: `"09:00-18:00"` |
| Заявки не приходят владельцу | не задан `OWNER_CHAT_ID` (шаг 5) |
| Бот отвечает «технические трудности» | проверьте ключ Anthropic, баланс и доступность API, смотрите лог в терминале |
