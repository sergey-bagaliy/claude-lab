# Сайт «Ремонт под контролем» — лендинг и демо-кабинет

Продающий сайт B2B-продукта «приложение для ремонтной компании» и интерактивный демо-кабинет на тестовых данных.
Сайт статический, без сборки и без внешних сервисов, поэтому готов к GitHub Pages.

> **Статус: черновик.** Название, список функций и цены — черновик, утвердить владельцем.
> Политику обработки персональных данных и текст согласия утвердить у юриста.

## Что внутри

| Файл | Что это |
|---|---|
| `index.html` | Лендинг: проблемы владельца → решение → функции → демо → тарифы → как начать → вопросы → заявка на демо |
| `demo/index.html` | Демо-кабинет с вымышленным объектом «Квартира 64 м²» |
| `privacy.html` | Шаблон политики обработки персональных данных (152-ФЗ, ст. 18.1) |
| `consent.html` | Шаблон согласия на обработку ПДн — отдельным документом, как требуется с 01.09.2025 |
| `404.html` | Страница «не найдено» |
| `assets/js/config.js` | **Настройки сайта**: черновик вкл/выкл, куда отправлять заявки, реквизиты |
| `assets/js/landing.js` | Меню, проверка и отправка формы |
| `assets/js/demo.js` | Логика демо-кабинета и тестовые данные |
| `assets/js/demo-art.js` | Рисованные иллюстрации вместо фотографий в фотоотчёте |
| `assets/css/*.css` | Стили |

## Демо-кабинет

- Разделы: **Обзор, Смета по этапам, График, Фотоотчёт, Акты, Оплаты по этапам, Чат**.
- Переключатель ролей: **Владелец / Прораб / Заказчик** — каждый видит объект по-своему (например, блок «Деньги по объекту» виден только владельцу).
- Что можно сделать руками:
  - заказчик согласует или отклоняет допработу — меняется итог сметы;
  - заказчик подписывает акт (код в демо: **1234**) — открывается оплата этапа — заказчик «оплачивает» (имитация);
  - владелец отмечает поступление оплаты;
  - прораб меняет готовность этапа, завершает этап — автоматически уходит акт на подпись и стартует следующий этап;
  - прораб добавляет фото с телефона (фото остаётся только в браузере) и допработу;
  - любой участник пишет в чат.
- Все данные вымышленные. Даты считаются от сегодняшнего дня, поэтому демо всегда «живое».
- Изменения хранятся в `localStorage` браузера. Кнопка «Сбросить демо» возвращает исходные данные.
- Прямые ссылки: `demo/#estimate`, `demo/#acts`, `demo/?role=client#payments` и т. п.

## Как опубликовать на GitHub Pages

В репозитории уже есть workflow `.github/workflows/pages-saas-remont.yml`, который публикует папку `saas-remont/site`.

1. Слить ветку с сайтом в `main`.
2. В репозитории на GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Открыть **Actions → Deploy saas-remont site → Run workflow** (или просто изменить любой файл сайта в `main`).
4. Адрес сайта появится в результате запуска, обычно `https://<логин>.github.io/<репозиторий>/`.

Важно: для приватного репозитория GitHub Pages доступен не на всех тарифах GitHub — проверьте в настройках Pages.
Все ссылки на сайте относительные, поэтому он работает и из подпапки `/<репозиторий>/`, и на своём домене.

## Перед запуском — список дел владельца

1. **Утвердить** название, функции, тарифы и цены. Затем в `assets/js/config.js` поставить `draft: false` — плашки «черновик» исчезнут.
2. **Подключить приём заявок** в `assets/js/config.js`:
   - `formEndpoint` — адрес своего обработчика на сервере **в России** (заявка содержит персональные данные; 152-ФЗ требует хранить их в базах на территории РФ), или
   - `contactEmail` — тогда форма откроет почтовую программу с готовым письмом.
   - Не подключайте зарубежные сервисы форм (Formspree, Google Forms и т. п.).
   - Пока ничего не указано, форма честно сообщает, что заявка не отправлена.
3. **Заполнить реквизиты** в `privacy.html`, `consent.html` (поля, выделенные жёлтым) и `owner` в `config.js`; показать документы юристу.
4. Если подключите веб-аналитику — допишите это в политику обработки ПДн.
5. Проверить, что название не занято: поиск по базе товарных знаков ФИПС.

## Как проверить локально

```bash
cd saas-remont/site
```

```bash
python3 -m http.server 8000
```

Затем открыть `http://localhost:8000/` в браузере.
