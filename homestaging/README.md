# Хоумстейджинг Краснодар — сайт и калькулятор

Статический лендинг услуги подготовки квартир к продаже и сдаче + калькулятор сметы и сравнения сценариев.
Без сборки, фреймворков и внешних скриптов: обычные HTML/CSS/JS, открываются с любого статического хостинга
(в том числе GitHub Pages по адресу вида `https://<user>.github.io/<repo>/`).

## Структура

```
homestaging/
  index.html              переадресация на site/ (корень GitHub Pages)
  shared/config.js        ВСЕ настройки: бренд, контакты, реквизиты, форма, аналитика, пакеты, работы и цены
  shared/base.css         цвета (светлая/тёмная тема), типографика, кнопки, поля, карточки
  site/index.html         лендинг
  site/site.css, site.js  стили и логика лендинга (пакеты, портфолио, форма, меню)
  site/privacy.html       политика обработки ПДн + текст согласия (шаблон, реквизиты из config.js)
  site/portfolio/         портфолио «до/после»: portfolio.js (данные) и README.md (как добавлять)
  calc/index.html         калькулятор «Смета подготовки и сравнение сценариев»
  calc/calc-core.js       чистые функции расчёта (браузер: window.HSCalc, Node: require)
  calc/calc-ui.js         связь формы калькулятора с расчётами, печать, ссылка «Поделиться»
  tests/calc-core.test.js юнит-тесты расчётов (node:test)
  checklist/              PDF-чек-лист для риелторов (делается отдельно; сайт ссылается на checklist/checklist.pdf)
  research/               исследование рынка — НЕ публикуется
../.github/workflows/pages.yml  публикация на GitHub Pages
```

## Локальный просмотр

```bash
cd homestaging
python3 -m http.server 8000
# открыть http://localhost:8000/site/  и  http://localhost:8000/calc/
```

Тесты калькулятора (из корня репозитория):

```bash
node --test homestaging/tests/
```

## Как редактировать `shared/config.js`

Все тексты и цифры, которые могут меняться, — в одном файле. После правки достаточно обновить страницу.

| Ключ | Что это | Пусто / `null` |
|---|---|---|
| `brand.name`, `brand.tagline` | Название и подзаголовок (подставляются в шапку, подвал, политику, печать) | — |
| `contacts.phone` | Телефон в любом формате | канал скрыт |
| `contacts.whatsapp` | Номер WhatsApp | канал скрыт |
| `contacts.telegram` | Имя пользователя без `@` или ссылка `https://t.me/...` | канал скрыт |
| `contacts.email` | Рабочая почта для заявок (не личная) | канал скрыт |
| `workingHours` | Режим работы для подвала | не показывается |
| `legal.name`, `inn`, `ogrnip`, `address` | Реквизиты оператора ПДн (подвал + политика) | в политике подсвеченные заглушки |
| `legal.policyDate` | Дата редакции политики | заглушка |
| `formEndpoint` | URL для POST заявки в JSON | форма предлагает отправить текст в мессенджер/почту |
| `analytics.yandexMetrikaId` | Номер счётчика Яндекс Метрики | счётчик не загружается |
| `packages[]` | Пакеты услуг (порядок = порядок на сайте) | — |
| `packages[].priceFrom` | Цена «от», ₽ | «Цена уточняется» на сайте, пустое подсвеченное поле «введите цену» в калькуляторе |
| `packages[].priceUnit` | `"за объект"` или `"за м²"` (в калькуляторе умножается на площадь) | — |
| `packages[].priceNote` | Оговорка к цене («до 45 м²», «ремонт — по смете») | не показывается |
| `packages[].areaPricing` | `{ baseArea, overPerM2 }`: цена «от» действует до `baseArea` м², больше — площадь × `overPerM2`; `overPerM2: null` — «уточняется после осмотра» | цена не зависит от площади |
| `packages[].durationDays` | Ориентировочный срок работ, дней | не показывается |
| `packages[].suggestFor` | Какое состояние квартиры в калькуляторе подсказывает пакет: `lived`, `empty`, `cosmetic` | — |
| `extras[]` | Отдельные работы для калькулятора | — |
| `extras[].unitPrice` | Цена за единицу, ₽ | пустое подсвеченное поле «введите цену» |
| `extras[].defaultQty` / `qtyFrom: "area"` | Количество по умолчанию / равно площади квартиры | — |

Пример заполнения цены:

```js
{ id: "standard", name: "Стандарт", /* … */ priceFrom: 1200, priceUnit: "за м²", durationDays: 7 }
{ id: "paint", name: "Покраска стен", unit: "м²", unitPrice: 450, defaultQty: 0, hint: "…" }
```

Число пишется без пробелов и кавычек. `id` пакетов не меняйте после публикации — они используются в ссылках
калькулятора (`?package=standard`).

Если меняете название бренда, поправьте также `<title>`, `meta description` и `og:*` в
`site/index.html`, `calc/index.html`, `site/privacy.html`, `index.html` — поисковики и мессенджеры читают их без JavaScript.

## Форма заявки

- **`formEndpoint` задан** — форма отправляет `POST` с `Content-Type: application/json`. Поля:
  `name, phone, type ("sale"|"rent"), typeLabel, address, area, packageId, packageName, comment, consent, page, createdAt, message, source`.
  Подойдёт Formspree/Getform, вебхук CRM (Битрикс24, amoCRM), Яндекс Cloud Function и т. п. Ответ не 2xx — показывается запасной вариант.
- **`formEndpoint` пуст** — форма собирает текст заявки и показывает кнопки: WhatsApp (текст подставляется),
  Telegram (текст копируется, чат открывается), почта (`mailto:` с темой и текстом), «Позвонить» и «Скопировать текст заявки».
- Если не задан ни один контакт и нет `formEndpoint`, на сайте видна плашка «Контакты ещё не настроены (заполните shared/config.js)».
- Из калькулятора кнопка «Обсудить смету» открывает форму с выбранным пакетом, площадью и суммой сметы в комментарии.

## Портфолио

Пока `window.HS_PORTFOLIO = []`, на сайте честная заглушка. Как добавлять реальные объекты «до/после», какие нужны
файлы и согласие владельца — в [`site/portfolio/README.md`](site/portfolio/README.md).

## Калькулятор: правила честности

- Цена, торг, срок и прочие эффекты подготовки — **только допущения пользователя**. По умолчанию подготовка «ничего не меняет»
  (изменение цены 0 %, тот же торг, тот же срок), и это прямо написано в интерфейсе, вердикте и печатной версии.
- Формулы — в блоке «Как считается» на странице и в шапке `calc/calc-core.js`. Разобранный пример с ручным расчётом —
  в `tests/calc-core.test.js`.
- «Поделиться расчётом» кодирует введённые значения в `#s=…` в адресе страницы; на сервер ничего не отправляется.
- «Сохранить / распечатать» печатает отдельный лист A4 (через «Печать → Сохранить как PDF» получается файл).

## Публикация на GitHub Pages

1. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Влейте изменения в ветку `main`. Workflow `.github/workflows/pages.yml` запускается при изменениях в `homestaging/**`
   (или вручную: **Actions → Deploy homestaging to GitHub Pages → Run workflow**).
3. Workflow прогоняет тесты калькулятора, собирает `_site` **только** из `homestaging/index.html`, `site/`, `calc/`, `shared/`
   и `checklist/` (если есть; без `build.js` и README), добавляет `.nojekyll` и публикует. `research/` и `tests/` на сайт не попадают.
4. Адрес: `https://<user>.github.io/<repo>/` → переадресация на `/site/`; калькулятор — `/calc/`.

GitHub Pages для **приватных** репозиториев доступен не на всех тарифах GitHub (на бесплатном — только для публичных).
Если репозиторий приватный и Pages недоступен, опубликуйте папку `_site` на любом статическом хостинге.
Свой домен: **Settings → Pages → Custom domain** (+ DNS-записи у регистратора).

## Один файл для просмотра без интернета

`dist/homestaging-krasnodar.html` — весь сайт в одном файле: лендинг, калькулятор и политика открываются поверх сайта,
чек-лист PDF скачивается кнопкой. Удобно отправить в мессенджере и открыть на компьютере.
Пересобрать после любых правок: `python3 homestaging/tools/build_single_file.py`.
Файл — черновик для просмотра (сверху плашка «Черновик»), на GitHub Pages он не публикуется.
